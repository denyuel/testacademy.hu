PART 1 Form Fields & Input Boundary Testing
7 Tasks
1.1. Full Name – Positive Baseline Test
Verify standard, valid text input handling in the Full Name field.
Steps:
  1. Type into the "Full Name" input: Peter Smith
  2. Click outside the field or press Tab to trigger the blur event.
❓ Question: Does any unexpected error appear? Does the border highlight normally?
1.2. Full Name – Lower Boundary Value (1 Character)
A single character is rarely a valid person name. How does the system handle it?
Steps:
  1. Clear the name field, and type only a single letter: A
  2. Fill out valid email (test@example.com), phone (+36301234567), date (tomorrow), and click the blue Submit button!
❓ Question: Did the validation accept the 1-character name or enforce a minimum length of 2-3 characters?
1.3. Full Name – Whitespace-Only (Space Bar Trap)
A classic form validation vulnerability: the field appears filled, but contains no characters.
Steps:
  1. Clear the name field completely.
  2. Press the Spacebar exactly 4 times ( ).
  3. Click the blue "Proceed to Booking & Payment →" button!
❓ Question: Did the confirmation modal open? Why is it a critical QA bug when a form accepts whitespace-only names?
1.4. Email Address – Format Validation Test
Verify how the email field responds to missing characters and malformed domains.
Steps:
  1. Type into Email: petersmith.example.com (missing the @ symbol).
  2. Click Submit. Observe the browser's native tooltip validation.
  3. Now type: petersmith@com (missing the period/domain dot). Click Submit again!
❓ Question: What exact error message did the browser show when @ was missing? Did it accept the dotless format?
1.5. Phone Number – Alphabetical Characters & Silent Failure
One of the most insidious software bugs: the user clicks Submit, but nothing happens.
Steps:
  1. In the "Phone Number" field, enter alphabetic letters: callmenow
  2. Ensure all other fields are valid (valid name, email, future date).
  3. Click the blue "Proceed to Booking & Payment →" button!
❓ Question: Did any error message appear? Did the confirmation modal open? Or did the UI silently freeze without feedback?
1.6. Date Picker – Booking in the Past
Steps:
  1. Click the "Starting Date" calendar picker.
  2. Select a date from last year (e.g. 2025-01-15).
  3. Fill out the form and submit.
❓ Question: Did the datepicker disable past dates? Did the system allow you to book an event in the past?
1.7. Notes Field – 250 Character Limit & Raw Database Alert
Test database buffer overflow and unhandled server exception feedback.
Steps:
  1. Copy this exact 265-character sample string:
    We would like to book this corporate workshop for our entire manual testing team across Central Europe. Please invoice our enterprise billing department at Test Academy International Ltd., Tax ID: 12345678-2-42, Registered Office: 1011 London, Fleet Street 42.
  2. Paste it into the "Special Requests / Notes" textarea.
  3. Click the blue "Proceed to Booking & Payment →" button!
❓ Question: What raw database error alert was displayed on screen? Copy the exact error alert text into your notes!
